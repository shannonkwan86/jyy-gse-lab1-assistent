# 第一版规格草案

状态：依据 2026-10-12 对话整理；已确认需求与设计建议分开记录。本文不是已完成的实现说明。

## 意图

通过建设、验证和长期演进个人助手练习 long horizon 软件工程。复用成熟组件以更快获取反馈，但不以直接使用现成产品代替项目开发。

当用户记得文章的词句、主题或用途，却忘记具体位置时，助手帮助找回候选、解释匹配理由并定位原文。文章找回为主，也支持综合多篇博客回答。

## 已确认范围

- Go；第一版自写受限 Agent 循环。
- 模型先接 DeepSeek。未来可换商汤，具体接口差异另行适配。
- 数据源为本机指定目录下已有 Markdown 博客，包括子目录，当前约 10–20 篇。
- 第一版不负责 Git 拉取或博客网站同步。
- 命令行交互，同一会话支持追问；退出后不要求恢复会话。
- 检索引入向量存储，并结合关键词检索。
- 查询前检查新增、修改、删除；索引反映变化。
- 记录调用次数及服务返回的 token 用量；不可获得的用量不伪造。

## 输出行为

文章找回：候选文章、匹配理由、原文片段和本机位置。多个合理候选应展示区别，不强行断言唯一目标。

综合回答：依据读取过的文章回答，关键结论附出处；资料不足或矛盾时明确说明。

出处包含文件、标题、起止行号、片段 ID、文件哈希及原文。

## 索引与模型边界

原文件为事实来源，索引可重建。修改文章应更新相关记录；删除文章应清除检索记录。未变内容应缓存 embedding，避免每次查询重新编码全部文章。

对话模型与 embedding 模型职责独立。当前采用百炼 text-embedding-v4 与 SQLite；实现默认值见 README。

目录中存在草稿、图片与其他内容，用户要求先不处理这些细节。过滤、front matter、图片/OCR、链接展开规则暂不确定；实现前不得擅自宣称这些格式已支持，也不得默认将整个目录上传。

## 验收方向（案例和阈值待确认）

1. 记得原文关键词时，目标文章进入候选，出处准确。
2. 只有语义描述时，检查向量检索对找回效果的贡献。
3. 多文章综合回答可追溯，引用支持结论。
4. 新增、修改、删除后结果同步；旧向量不作为当前证据。
5. 同会话追问可指向上轮候选；新会话不依赖旧会话。
6. 无结果、API 失败、索引失败分别呈现，不能把服务失败当成资料不存在。
7. 能查看工具调用与模型用量，便于诊断成本和失败。

以上是验收方向，不是已通过的测试。真实案例、可接受延迟及成本预算待定。
