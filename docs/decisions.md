## 首次审查后的修复与重构（2026-10-12）

- 保留 Go、SQLite、混合检索和 JSON 动作协议；按职责拆分 CLI 组装/交互、Agent 动作/结果校验、Markdown 解析/文件读取、索引同步与搜索。相关生产函数不超过 50 行，不新增依赖。
- 正文独立引用标记与引用列表双向对应，并在发布前复核全部已读证据；修复原实现只检查最终引用列表的契约缺口。允许无引用的资料不足结果，不能伪造引用。
- 普通文件类型检查和 context 传递避免扫描 FIFO，并支持遍历、读取与切分阶段合作式取消；不宣称单个底层文件系统调用可立即中断。
- 数据库在 SQLite 打开前创建/收紧至 0600，已有辅助文件同样处理；路径使用文件 URI 编码，避免路径字符被解释为数据库选项。未扩大为加密或多实例协调。
- 无变化快照跳过索引重写；缓存按所需键每批最多 100 条读取，embedding 每批仍最多 10 条。有变化时仍完整事务发布，未改为复杂的逐文档增量更新。保留精确向量遍历，待真实规模指标再优化。
- 独立审查发现本轮输入通道关闭顺序导致的取消回归，新增用例先复现失败，再修复为所有退出路径先报告结束原因，复查通过。

## 搜索工具自动读取证据（2026-10-12）

真实查询“关于ICPC 南昌站 邀请赛的文章”出现 search → final 后报 citation was not read：搜索已返回正文，但登记可引用证据依赖模型额外请求 read，协议与数据呈现不一致。

改为 search 内部调用 ReadContext 读取并校验全部候选（最多 5 个），全部成功才登记并返回。模型动作缩减为 search/final；底层混合排序不变，最终仍检查引用身份、正文标记与全部已读证据版本。候选失效时明确失败，不跳过校验或无限重试。代价是每次搜索最多增加 5 次本地证据读取。

修复后用户在自己的命令行重跑原始 ICPC 南昌站查询并确认成功；助手未重复调用真实服务。模型动作模拟测试验证程序拒绝越权请求，但真实提示注入抵抗能力仍未全面评估。
